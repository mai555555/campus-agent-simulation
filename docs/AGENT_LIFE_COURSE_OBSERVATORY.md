# Agent 生命历程观察台设计

## 1. 文档目的

本文定义“Agent 生命历程观察台”（Agent Life-Course Observatory）的研究定位、产品体验、数据口径和实施边界。

观察台建立在现有校园平行世界之上。3D 世界负责呈现 Agent 此刻正在做什么；生命历程观察台负责整理 Agent 过去经历了什么、状态如何变化、关系如何演化，以及这些变化如何进一步参与群体形成。

本设计只研究一个持续运行的校园世界，不引入平行世界、复制世界或对照世界。

## 2. 核心问题

观察台希望回答三个层次的问题：

1. 个体：一个 Agent 经历了什么，哪些经历构成了重要转折？
2. 关系：共同经历、合作、冲突和信息交换如何伴随关系变化？
3. 群体：个体和关系的长期变化如何参与群体形成、分裂和角色分化？

核心表达链条为：

```text
事件经历
-> Agent 感知与记忆
-> 行为选择
-> 个体状态变化
-> 关系变化
-> 群体变化
```

观察台不是给 Agent 编写新的故事，而是把数据库中已经发生、已经记录的行为和状态组织成可追溯的生命历程。

## 3. 研究定位

### 3.1 适合支持的研究

- 生命历程与关键转折事件分析。
- 事件序列和行为轨迹分析。
- 记忆对后续决策的使用情况分析。
- 关系建立、强化、紧张和中断的过程分析。
- 群体形成、成员角色变化和集体目标推进分析。
- 长期人格一致性、目标持续性和行为适应性分析。
- 从个体事件到关系和群体结果的过程追踪。

### 3.2 不能直接声称的结论

- 不能把虚拟 Agent 的表现直接推广为真实学生行为。
- 不能仅凭事件先后关系证明因果关系。
- 不能把 LLM 生成的解释当作已经验证的心理事实。
- 不能为了形成完整故事而补写数据库中没有发生的事件。

因此，界面统一使用“影响路径”“关联经历”“可能解释”等表达，不使用“该事件导致了该结果”这类未经验证的因果表述。

## 4. 与现有系统的关系

现有系统已经保存了观察台所需的大部分原始数据：

| 现有数据 | 生命历程用途 |
| --- | --- |
| `residents` | 身份、角色、初始目标、当前位置 |
| `agent_profiles` | 当前精力、情绪、任务、感知和时间预算 |
| `memories` | 个人经历、日记、重要性、记忆类型和来源 |
| `simulation_action_logs` | 感知、检索记忆、决策、执行和环境反馈 |
| `agent_learning` | 行动后的经验记录和评分变化 |
| `long_term_goals` | 长期目标及当前进度 |
| `relationships` | 当前基础关系强度 |
| `relationship_dynamics` | 当前好感、信任、合作、竞争和冲突 |
| `group_goals` | 群体目标、成员和推进状态 |
| `world_event_stream` | 连续世界事件、tick、地点和关联 Agent |
| `agent_action_plans` | 计划意图与实际行为的偏离 |
| `observer_sessions` | 观察者关注记录，用于识别观察者效应 |

现有 `/api/agents/{id}/timeline`、`/memories`、`/simulation-logs` 和 `/social-graph` 可以作为首版数据来源。观察台不应再创建一份彼此独立的“故事数据”。

## 5. 体验设计

### 5.1 入口

在当前观察者界面增加一级入口“生命历程”。入口默认打开当前选中的 Agent，也可以在观察台中切换 Agent。

查看生命历程属于只读行为：

- 不触发 Agent 反思。
- 不增加记忆。
- 不触发模型调用。
- 不提高该 Agent 的 tick 优先级。
- 不改变世界运行状态。

这样可以避免研究界面本身改变被观察对象。

### 5.2 页面信息架构

```text
顶部：Agent 身份 / 当前状态 / 观察时间范围

第一栏：生命阶段摘要
初始目标 / 当前目标 / 当前状态 / 主要关系 / 群体身份

第二栏：关键经历时间线
按时间展示转折事件、重要记忆、行动和阶段节点

第三栏：经历影响路径
前置经历 -> 决策 -> 行动 -> 状态变化 -> 后续事件

第四栏：关系演化
重要关系、共同经历、合作、冲突和当前关系状态

第五栏：群体演化
加入或退出群体、群体角色、共同目标和影响范围

底部：证据与研究边界
原始日志、记忆、事件引用、置信等级和解释说明
```

### 5.3 Agent 生命阶段摘要

摘要回答“这个 Agent 现在是谁”：

- 初始身份、性格和目标。
- 当前任务、位置、精力和情绪。
- 当前长期目标及进度。
- 最重要的近期经历。
- 最稳定或变化最大的关系。
- 当前所属群体和承担角色。
- 当前阶段的行为特征，例如“社交增加”“学习活动集中”“频繁偏离计划”。

摘要中的每个判断都必须能跳转到对应事件或统计依据。

### 5.4 关键经历时间线

时间线支持以下筛选：

- 时间范围：最近一天、7 天、30 天、全部。
- 类型：行动、关系、目标、群体、信息、环境、日记。
- 重要程度：全部、重要、关键转折。
- 证据来源：事件流、行动日志、记忆、日记、计划。

重复的低信息 tick 行动继续沿用现有聚合逻辑，显示为“持续 N 次”，避免让机械重复淹没真正经历。

### 5.5 事件详情

点击事件后展示：

```text
发生了什么
Agent 当时感知到了什么
Agent 检索了哪些既有记忆
Agent 为什么选择该行动
行动是否成功
个体状态发生了什么变化
涉及哪些关系或群体
之后出现了哪些关联事件
证据来自哪些原始记录
```

如果当前数据无法支持某一项，明确显示“暂无可验证记录”，不能由 LLM 自动补全。

## 6. 关键事件识别

首版采用可解释的规则评分，不直接让 LLM 决定什么是关键事件。

建议分数由以下部分组成：

| 维度 | 判断依据 |
| --- | --- |
| 记忆重要性 | `memories.importance` |
| 行动结果 | 成功、失败、降级观察或异常 |
| 目标变化 | 长期目标进度明显变化或完成 |
| 关系影响 | 聊天、合作、冲突及关系指标变化 |
| 群体影响 | 创建、加入、退出群体或推进群体目标 |
| 信息影响 | 接收、传播或失真外部资讯 |
| 持续影响 | 后续多个 tick 仍检索或提及该经历 |
| 扩散范围 | 事件关联多个 Agent、地点或群体 |
| 稀有程度 | 相对该 Agent 日常行为是否少见 |

建议输出三个等级：

```text
普通经历：构成日常轨迹
重要经历：状态、目标或关系出现可观察变化
关键转折：变化持续存在，且关联多个后续事件
```

评分公式和阈值必须版本化，例如 `turning-point-rules-v1`，以便后续研究复查。

## 7. 经历影响路径

### 7.1 链接原则

事件之间的连接按照证据强度分级：

| 等级 | 含义 | 示例 |
| --- | --- | --- |
| 直接 | 数据中存在明确引用 | 决策日志明确检索了某条记忆 |
| 强关联 | 同一 tick、同一行动或明确目标对象 | 聊天行动与双方关系更新 |
| 时序关联 | 前后发生且状态变化方向一致 | 冲突后连续减少社交 |
| 模型解释 | 由摘要模型提出的可能联系 | 只能作为假设，不能作为事实 |

界面必须显示连接等级。默认只绘制“直接”和“强关联”，用户主动开启后才显示“时序关联”和“模型解释”。

### 7.2 防止伪因果

- 不把时间相邻自动解释为因果。
- 不把 Agent 的行动理由视为客观事实。
- 不隐藏与当前解释相冲突的事件。
- 模型摘要必须引用事件 ID，无法引用时不进入正式摘要。
- 同时显示环境、计划和观察者关注等替代解释。

## 8. 关系与群体观察

### 8.1 关系演化

关系卡片展示：

- 对方 Agent 和当前关系指标。
- 第一次有记录的互动。
- 最近一次互动。
- 共同经历数量。
- 合作、冲突和信息交换事件。
- 关系变化的关键节点。

当前 `relationship_dynamics` 主要保存最新状态，无法完整还原每次指标变化。首版只能展示“当前关系 + 有记录的共同经历”，不能伪造历史曲线。

后续如需真实关系曲线，应增加只追加的关系变化记录，每次保存：

```text
from_resident_id
to_resident_id
tick_id
event_id
affinity_delta
trust_delta
cooperation_delta
competition_delta
conflict_delta
reason
created_at
```

### 8.2 群体演化

群体视图展示：

- 当前活跃群体和成员。
- 群体形成时涉及的事件。
- 成员加入、退出和角色变化。
- 群体目标进度。
- 群体内部高频互动关系。
- 与其他群体的合作或冲突。

群体视图不能只按 LLM 文本判断群体，优先使用 `group_goals`、协作记录和关系网络结构。

## 9. 数据缺口与建议扩展

### 9.1 首版不新增表也能完成

首版可以只读聚合现有数据，完成：

- Agent 身份与当前状态摘要。
- 全量行动和记忆时间线。
- 关键经历规则评分。
- 决策对检索记忆的直接引用。
- 当前关系网络和共同经历。
- 当前群体目标和成员。

### 9.2 后续需要补充的历史数据

为了真正观察“如何变化”，建议后续按独立 PR 增加：

1. `agent_state_snapshots`：每个关键事件或阶段保存精力、情绪、位置、任务和目标进度。
2. `relationship_change_events`：保存每次关系指标增量及关联事件。
3. `life_course_event_links`：保存经过规则确认的事件连接、证据类型和置信度。
4. `life_course_summaries`：缓存阶段摘要，并记录摘要版本、覆盖时间和证据事件 ID。

这些表保存派生结果或历史快照，不替代 `world_event_stream` 和 `simulation_action_logs` 原始记录。

## 10. API 草案

首版建议新增只读接口：

```text
GET /api/agents/{resident_id}/life-course/overview
GET /api/agents/{resident_id}/life-course/events?from_day=1&to_day=30&type=all
GET /api/agents/{resident_id}/life-course/turning-points?limit=10
GET /api/agents/{resident_id}/life-course/relationships
GET /api/agents/{resident_id}/life-course/groups
GET /api/life-course/group-evolution?from_day=1&to_day=30
```

所有派生对象统一包含：

```json
{
  "evidence": [
    {"source": "simulation_action_logs", "id": 120},
    {"source": "memories", "id": 338}
  ],
  "analysis_version": "life-course-v1",
  "confidence": "direct"
}
```

分页接口必须提供稳定游标或 `limit + offset`，避免长期运行后一次加载全部历史。

## 11. 摘要模型的使用边界

LLM 可以用于：

- 将已经筛选的关键事件压缩成阶段摘要。
- 为研究者解释字段和事件类型。
- 提出需要进一步查看的关联经历。

LLM 不可以用于：

- 创造数据库中不存在的经历。
- 推断没有记录的情绪、动机或关系。
- 修改关键事件分数。
- 在没有证据 ID 的情况下生成正式结论。

首版默认不调用 LLM，由规则聚合生成观察台。阶段摘要模型作为后续可选功能，并单独计入模型预算。

## 12. 验收标准

首版实现应满足：

1. 可以从任一 Agent 打开独立生命历程视图。
2. 可以查看完整历史并按时间、事件类型和重要程度筛选。
3. 每个关键事件可以回到至少一条原始数据记录。
4. 可以看到决策明确使用过的历史记忆。
5. 可以查看当前关系、共同经历和群体参与情况。
6. 重复 tick 不会淹没时间线。
7. 长历史使用分页加载，不阻塞主页面。
8. 打开观察台不会触发模型调用或改变世界状态。
9. 数据不足时明确显示缺口，不生成补充事实。
10. 移动端和桌面端均可阅读，文本和图表不重叠。

## 13. 分阶段实施

### 阶段一：只读个人生命历程

- 聚合现有身份、记忆、行动日志、目标、关系和群体数据。
- 实现关键经历规则评分。
- 实现个人时间线、事件详情和证据引用。
- 不修改数据库结构，不调用 LLM。

### 阶段二：状态与关系变化历史

- 增加 Agent 状态快照。
- 增加关系变化事件。
- 展示情绪、精力、目标和关系的真实历史曲线。
- 将快照和变化关联到 `world_event_stream`。

### 阶段三：经历影响链与群体视图

- 建立事件链接和置信等级。
- 展示个体经历向关系和群体扩散的过程。
- 增加群体形成、分裂和角色变化视图。
- 增加研究导出字段。

### 阶段四：证据约束的阶段摘要

- 对关键事件生成阶段性生命历程摘要。
- 强制返回证据事件 ID。
- 记录模型、Prompt 版本、Token 和费用。
- 允许研究者查看摘要所依据的原始记录。

## 14. 推荐 PR 拆分

```text
PR 1: docs - 生命历程观察台设计与数据口径
PR 2: feat - 只读 life-course 聚合接口
PR 3: feat - 个人生命历程观察台 UI
PR 4: data - 状态快照与关系变化记录
PR 5: feat - 经历影响链和群体演化视图
PR 6: feat - 证据约束的阶段摘要
```

每个 PR 保持单一目标。涉及数据库的 PR 必须同步更新 `app/schema.py`、`docs/supabase_schema.sql`、迁移说明和既有数据兼容策略。

## 15. 一句话定位

> Agent 生命历程观察台通过可追溯的事件、记忆、决策、关系和群体记录，展示经历如何伴随个体状态与社会结构持续演化，使校园平行世界从“正在发生什么”进一步走向“这些变化是怎样一步步形成的”。

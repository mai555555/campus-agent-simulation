# 校园 Agent 平行世界：空间社会智能升级路线

## 1. 文档目的

本文定义校园 Agent 平行世界从“语言驱动的多 Agent 展示系统”升级为“可观察、可干预、可复现、可解释的空间社会智能实验平台”的产品方向与工程路线。

本文是后续空间智能相关需求、架构设计、实验设计和阶段验收的共同依据。具体实现仍应拆分为独立功能分支和 PR，不在本路线文档 PR 中直接修改运行代码。

## 2. 项目定位

### 2.1 当前基础

当前系统已经具备：

- 校园 Agent 的角色、目标、记忆、关系、位置和日程。
- 教学楼、图书馆、食堂、宿舍区、商业街、操场、校务处等校园空间。
- 天气、时间、拥挤度、空间开放状态和校园事件。
- Agent 感知、记忆检索、决策、规则执行、反馈和沉淀闭环。
- Three.js 校园展示、人物详情、关系网络、行动时间线和校园日报。
- SQLite/PostgreSQL 持久化与 Render 部署基础。

当前的空间仍主要表现为地点标签和空间状态。Agent 可以决定“前往图书馆”，但尚未完整理解道路、入口、距离、视线、遮挡、局部人流和沿途接触。

### 2.2 目标定位

项目的下一阶段目标是：

> 构建一个具有有限感知、空间记忆、路径约束和社会关系的校园实验世界，研究空间条件如何影响个体行动、群体形成、信息传播和政策干预结果。

空间智能不是单纯增加更精细的 3D 画面，而是让空间成为能够约束感知、决策、行动和社会关系的计算系统。

## 3. 核心原则

### 3.1 世界真实状态与 Agent 主观认知分离

系统必须区分：

- 世界中真实存在的对象、人物、事件和空间状态。
- Agent 当前能够看见、听见或接触到的信息。
- Agent 从他人、公告或外部资讯获得的信息。
- Agent 根据记忆和经验形成的推测。
- Agent 尚不知道或判断错误的内容。

Agent 不应直接读取完整世界数据库作为决策上下文。

### 3.2 LLM 与确定性空间引擎分层

LLM 负责：

- 社会意图。
- 目标权衡。
- 对话与协商。
- 高层行动选择。
- 对经历的解释和反思。

空间与规则引擎负责：

- 距离和路径计算。
- 开放状态与容量检查。
- 移动时间和能量成本。
- 视线、邻近和遮挡判断。
- 碰撞、排队和空间占用。
- 真实世界状态写入。

LLM 不直接修改坐标，也不能绕过空间规则。

### 3.3 研究证据优先于叙事效果

每次空间行动都应形成可追踪证据链：

```text
世界状态
→ Agent 可感知范围
→ Agent 主观空间模型
→ 检索到的空间记忆
→ 社会目标与空间计划
→ 规则执行结果
→ 世界、关系与记忆变化
```

个人日记和校园日报是运行结果的叙事摘要，不能代替底层实验数据。

### 3.4 可复现优先于规模

在扩大 Agent 数量或接入高精度物理引擎之前，优先完成：

- 实验批次编号。
- 随机种子。
- 配置快照。
- 世界状态快照。
- 暂停、恢复和回放。
- 统一时间字段。
- 研究数据导出。

## 4. 目标能力模型

### 4.1 校园空间图

每个空间至少包含：

- 唯一标识和名称。
- 空间类型与功能标签。
- 二维或三维坐标。
- 空间边界。
- 容量和当前占用。
- 开放时间和运行状态。
- 入口、出口和相邻空间。
- 噪声、照明、安全和资源状态。

道路或连接边至少包含：

- 起点和终点。
- 距离和基础耗时。
- 通行状态。
- 拥堵系数。
- 天气影响系数。
- 无障碍属性。
- 风险等级。

### 4.2 连续移动

移动不再是地点字段的瞬时切换，而是一个可中断的连续过程：

```text
选择目的地
→ 规划路径
→ 进入路径节点
→ 消耗时间与能量
→ 产生沿途感知和接触
→ 到达或重新规划
```

空间关闭、道路拥堵、天气变化和突发事件可以触发重新规划。

### 4.3 局部感知

Agent 的感知由以下因素决定：

- 当前位置与朝向。
- 感知半径。
- 空间边界和遮挡。
- 光照与噪声。
- 目标对象的距离。
- 注意力和当前任务。
- 信息渠道。

感知结果必须记录来源、时间和置信度。

### 4.4 空间记忆

空间记忆至少记录：

- 发生时间。
- 具体位置。
- 观察位置和信息来源。
- 附近人物与对象。
- 事件内容。
- Agent 的行动与结果。
- 重要性和可信度。

空间记忆应参与后续目的地选择、路径规划、风险回避和社交决策。

### 4.5 空间社会行为

后续逐步支持：

- 人际距离和个人空间。
- 身体朝向和共同关注目标。
- 排队与插队。
- 偶遇、同行和回避。
- 小群体站位与 F-formation。
- 拥挤导致的移动成本、压力和冲突。
- 长时间共处对熟悉度和关系的影响。

## 5. 分阶段实施计划

### 阶段 0：工程与实验基础

目标：使后续空间机制能够被独立开发、测试和复现。

主要任务：

- 拆分集中在 `app/main.py` 的空间、Agent、记忆、社会关系和模拟调度逻辑。
- 引入正式数据库迁移机制。
- 增加实验批次、随机种子、配置快照和运行元数据。
- 增加世界快照、暂停、恢复和回放能力。
- 建立研究数据导出格式。
- 补充单元测试、接口测试和模拟回归测试。

验收标准：

- 同一配置和随机种子能够得到可比较的运行过程。
- 每次实验可以独立识别、导出和回放。
- 后续空间模块不需要继续堆叠到单一主文件中。

### 阶段 1：空间拓扑与路径规划

目标：让 Agent 在有距离和通行约束的校园中移动。

主要任务：

- 建立校园空间节点与道路边。
- 为 Agent 增加路径、移动进度和预计到达时间。
- 使用 A* 或 Dijkstra 计算路径。
- 将天气、拥堵、开放状态和体力纳入路径成本。
- 在 Three.js 中显示连续移动和当前路径。

验收标准：

- Agent 不能穿越未连接空间或关闭入口。
- 同一目的地可以根据环境产生不同路线。
- 移动过程可以被暂停、中断和重新规划。

### 阶段 2：局部感知与空间记忆

目标：限制 Agent 的知识范围，并让空间经历影响未来决策。

主要任务：

- 实现邻近、视野和遮挡计算。
- 区分亲眼观察、听闻、公告和推测。
- 建立空间记忆结构和检索机制。
- 在决策日志中保存 Agent 当时实际可见的信息。
- 支持感知错误、信息过期和置信度变化。

验收标准：

- 不同位置的 Agent 对同一事件拥有不同认知。
- Agent 不能使用未感知或未接收的信息进行决策。
- 历史空间经历能够改变路线或目的地选择。

### 阶段 3：空间社会行为

目标：让人际接触和群体结构从空间共处中产生。

主要任务：

- 记录接触距离、共同停留时长和同行关系。
- 实现排队、个人空间、回避和小群体站位。
- 将空间接触纳入关系变化和信息传播。
- 增加人流热力图、接触网络和轨迹回放。

验收标准：

- Agent 的交流对象受到实际空间接触约束。
- 拥挤度能够影响移动、等待、情绪和冲突概率。
- 可以从轨迹数据重建关键群体事件。

### 阶段 4：研究实验与分析

目标：形成可运行、可比较、可解释的空间社会实验。

主要任务：

- 支持基线、干预、恢复和批次对照。
- 固化三个空间智能基准实验。
- 导出 Agent-Action、Space-Time、Contact Edge、Relationship Edge 和 Event Stream 数据。
- 建立描述统计、时间序列、网络分析和空间热力图。

验收标准：

- 每个实验有明确的自变量、因变量和对照条件。
- 实验结果可以从底层数据而非日记文本中验证。
- 研究报告能够明确区分模拟结果与现实结论。

### 阶段 5：高精度物理能力评估

仅在以下研究需求成立时评估 Unity、Unreal Engine、Omniverse 或 Isaac Sim：

- 高密度人群碰撞与疏散。
- 机器人或 Agent 对物体的抓取和协作操作。
- 复杂建筑内部导航与精确遮挡。
- 力矩、重心和刚体动力学。

在此之前，优先使用 Three.js、空间图和确定性规则引擎完成社会研究所需能力。

## 6. 三个基准实验

### 6.1 图书馆关闭实验

研究问题：关键学习空间关闭后，Agent 如何重新规划路径，替代空间是否产生拥挤，接触网络是否发生变化？

主要指标：

- 路径变化和额外移动成本。
- 各空间人流变化。
- 到达失败和重新规划次数。
- 偶遇、聊天、合作和冲突变化。
- 关系网络变化。

### 6.2 食堂拥挤实验

研究问题：排队、容量和个人空间如何影响等待、回避、情绪及冲突？

主要指标：

- 排队长度和等待时间。
- 放弃、换队和错峰行为。
- 人际距离与冲突事件。
- 服务效率和满意度。

### 6.3 局部资讯传播实验

研究问题：当资讯只有部分 Agent 可见时，空间接触和信任关系如何共同影响传播？

主要指标：

- 首次感知位置和时间。
- 传播路径与传播层级。
- 空间接触边与信任边的贡献。
- 未接收、误传和延迟接收情况。

## 7. 建议的数据层

- `Experiment Run`：实验批次、配置、随机种子、代码版本和模型版本。
- `World Snapshot`：指定 tick 的环境、空间、Agent 和事件状态。
- `Agent Trajectory`：Agent、时间、坐标、路径节点和移动状态。
- `Perception Record`：观察者、目标、来源、距离、置信度和时间。
- `Contact Event`：相关 Agent、位置、距离、持续时间和互动结果。
- `Space-Time`：空间状态、容量、占用、拥挤度和开放状态。
- `Action Evidence`：感知、记忆、计划、执行、反馈和成本。
- `Relationship Edge`：关系方向、信任、合作、竞争、冲突和更新时间。

具体表结构和 API 契约应在对应实现阶段单独设计和评审。

## 8. 非目标

本路线当前不以以下内容为目标：

- 通过增加 Agent 数量制造表面复杂度。
- 将更精细的 3D 美术等同于空间智能。
- 让 LLM 直接控制坐标、碰撞或数据库写入。
- 在没有随机种子和对照实验时宣称因果结论。
- 使用模拟结果评价具体真实学生或群体。
- 在社会研究需求尚未明确时引入高成本物理引擎。

## 9. 项目级成功标准

当以下条件同时满足时，可以认为项目完成了从校园 Agent 展示系统到空间社会智能实验平台的关键升级：

- Agent 的知识受到位置、视野、经历和信息渠道限制。
- 空间能够拒绝、延迟或改变 Agent 的行动。
- 移动、接触、拥挤和关系变化形成完整数据链。
- 空间干预能够产生可追踪的直接与间接影响。
- 同一实验可以通过批次、配置和随机种子复现。
- 研究者可以导出数据并解释每个关键行为的证据来源。
- 产品界面能够回放轨迹、感知、决策和世界变化。

## 10. Git 与交付约定

- 不直接在 `main` 上开发。
- 每个阶段从最新 `main` 创建 `feat/...`、`fix/...` 或 `docs/...` 分支。
- 单个 PR 只承担一个清晰目标。
- PR 必须说明变更内容、验证方式、数据库影响、环境变量影响和部署配置影响。
- 数据结构变更必须附带迁移和回滚说明。
- 合并后由部署平台从 `main` 发布，功能分支不直接作为正式线上版本。
